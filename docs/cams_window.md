# CAM 4채널 새 창 (R17)

관제실 두 번째 모니터에 CAM 4채널을 크게 띄우는 화면. 대시보드는 한 모니터에 그대로 둔다.

## 여는 방법

- 대시보드 상단 **[CAM 4채널 새 창 ↗]** 또는 상세 보기의 CAM 4채널 카드 **[새 창으로 크게 ↗]**
- 창 이름이 하나(`dock_cams`)라 두 번 눌러도 창은 하나 — 이미 열려 있으면 그 창을 앞으로 가져온다.
- 새 창이 자기 크기·위치를 `localStorage`(`camsWin`)에 적어 두고, 다음에 열 때 그 자리로 연다.
- 브라우저가 팝업을 막으면 안내가 뜬다 → 주소창 오른쪽에서 이 사이트 팝업 허용. 주소 `/cams`를 직접 열어도 된다.

## 화면 · 조작

| 동작 | 결과 |
|---|---|
| 채널 누르기 · Enter | 그 채널 1개 크게 ↔ 다시 누르면 4분할 |
| 1 ~ 4 | 그 채널 크게 |
| Esc · [4분할] | 4분할로 |
| F · [전체 화면] | 브라우저 전체 화면 켜고 끄기 |
| 채널 두 번 누르기 · [상세] | 대시보드 창의 그 채널 상세(`#cam/CAM-0n`) |
| [대시보드] | 대시보드 창을 앞으로(없으면 새로 연다) |

- 채널마다: 번호 · 채널명, **LIVE(영상)/시뮬레이션** 배지, 호퍼 상태 칩(원활/주의/혼잡/정지 · %), 시각, 요약(하역 n/3 · 대기 n).
- 그리기는 대시보드와 같은 파일 `web/cam_view.js` — 박스 · 추적 ID · 구역 · 위험 반경 · 아차사고 강조 · 대기장 접근 거리선이 똑같이 보인다.
- **빨간 테두리(깜빡임)**: 그 채널에
  - 안전 경고가 열려 있거나(호퍼),
  - 최근 3분(시뮬레이션) 안에 아차사고가 기록됐거나(`/api/cams/live`),
  - 지금 영상 장면에서 위험이 보일 때(덤프 반경 안 사람 · 움직이는 트럭과 사람 2m 이하).
  해제되면 원래대로. 아래 빨간 띠에 무엇 때문인지 적는다.

## 데이터 · 권한

- `/cams`: 관제 · 현장만(로그인 안 하면 `/login`, 운전자는 `/m/`).
- 상태: `GET /api/cams/live` 1초마다 — 채널별 혼잡 · 시뮬레이션 그림용 하역장 · 위험. 관제 전체 상태(`/ws`)는 관제 전용이라 새 창은 이 작은 응답만 쓴다.
- 영상 · 탐지 결과: `GET /api/cams`, `/media/*` (관제 · 현장). 현장 담당자는 **담당 하역장 채널만**(대기장 담당 `YARD`이면 CAM-04).
- 이벤트 형식은 바뀌지 않았다.

## 두 모니터 시연 순서 (리허설 체크리스트)

1. 대시보드를 모니터 1, [CAM 4채널 새 창 ↗]으로 연 창을 모니터 2로 옮긴다(다음부터 그 자리에 열림).
2. 대시보드에서 시뮬레이션 시작 → 새 창 상단 시각이 같이 간다.
3. 08:07 무렵 대기장 아차사고 → 대시보드 맵 대기장 빨간 표식 · 알림, 새 창 4번(CAM-04) 빨간 테두리.
4. 새 창에서 4 → CAM-04 크게, 영상 8~12초 거리선 · "아차사고 위험" 띠 → Esc로 4분할.
5. [상세] → 대시보드 창이 CAM-04 상세로 바뀌고 앞으로 온다.
6. 대시보드 [CAM 4채널 새 창 ↗]을 다시 눌러도 창이 하나뿐인지.
7. 운전자 계정으로 `/cams` → 운전자 화면으로 돌아가는지, 현장(호퍼 A) 계정은 CAM-01만 보이는지.

## 한계

- 영상은 대시보드와 새 창이 각자 재생하므로 두 창의 영상 시각은 서로 다르다(같은 영상의 같은 순간이면 그림은 같다). 대시보드 쪽 재생을 멈추는 것(I7)은 다음 라운드.
- 오버레이 켜고 끄기(I6) · 모바일 전체 화면(I8) · 같은 창 전체 화면 버튼 병행(I9) · 1+3 배치와 소리(I10)는 이번에 하지 않았다(새 창의 [전체 화면]은 있음).
