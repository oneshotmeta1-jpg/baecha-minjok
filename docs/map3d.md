# 3D 매핑 카드 · 안전 경고 깜빡임 (전달 패키지 반영)

출처: `3D매핑_전달패키지.zip` — `1_코드/map3d.js` · `safety-blink.js`(4번 데모 안 코드와 같음을 확인)를 `web/map3d.js` · `web/safety-blink.js`로 그대로 씀.
정적 경로는 이 서버의 `/web/...`(요청서 예시 `/static/...` 대신). 두 스크립트는 `web/index.html` 본문 스크립트보다 먼저 불러온다.

## 들어간 곳

| 위치 | 내용 |
|---|---|
| 구역 상세(`#cam/CAM-0n`) 오른쪽 열, [탐지 목록] 바로 위 | `Map3D.mount(#m3card, {zone, height: 168})` — 켰을 때 카드 약 210px, 껐을 때 헤더 42px. 켬/끔은 `localStorage` `map3d.on` |
| CAM 탭 바꿈 | `setZone`: CAM-01 A · CAM-02 B · CAM-03 C · CAM-04 W |
| 탐지 목록 ↔ 핀 | 행 `data-tid="#n"` = 핀 `id`. 행에 마우스 → `highlight`, 핀에 마우스 → 행 강조. 영상 채널도 탐지 목록을 시뮬레이션 상태(추적 ID)로 채운다(전에는 비어 있었음) |
| 관제 화면 배치도 | `SafetyBlink.attach(#mapBd)` — 구내 관제 맵은 베이 좌표, 평면도는 야드 중심에서 위치(%)를 계산하므로 확대·이동해도 따라간다. 야드 칩 영역(box)도 함께 깜빡임 |
| 상단 빨간 띠 | 관제 화면 · 구역 상세 둘 다. 관제 확인 전 1초 깜빡임 → 확인 뒤 빨간색 고정 |

## 상태 매핑 (서버 상태 → `items`)

| 서버 상태 | state |
|---|---|
| 하차 중 + 열린 안전 경고(덤프 반경) | `danger` (+ `bays[n] = 'stop'`) |
| 하차 중 + 열린 안전 경고(후진 경로) | `reverse` (+ `stop`) |
| 하차 지연 | `delay` (`ratio` = 지연 배수) |
| 하차 중 · 적재함 15° 이상 | `unload` |
| 하차 중 · 적재함 15° 미만(베이에 막 들어옴) | `enter` |
| 그 호퍼로 호출 이동 중(가장 먼저 도착하는 1대) | `call` |
| 빈 베이 · 그 베이로 오는 차 있음 / 없음 | `bays[n] = 'reserved'` / `'empty'` |
| 대기장: 긴급 · 대기 초과 · 승인 대기 · 그 밖 | `urgent` · `overdue` · `approval` · `wait`(순번 배지) |

`done`(하역 완료) · `unknown`(미등록 차량)은 지금 서버 상태에 해당 값이 없어 쓰지 않는다.

## 안전 경고 흐름

1. 경고 발생(`SAFETY_ALERT`) → 배치도 · 카드 · 띠가 함께 1초 깜빡임.
2. **관제 확인** — 띠 [관제 확인] 또는 카드 헤더 "안전 경고 N" 배지 → `POST /api/safety/{id}/seen` → `SAFETY_SEEN` 기록, 상태 `safety_open[].seen = true`.
   실시간 상태로 모든 화면 · 다른 접속자에게 퍼져 세 곳 모두 빨간색 고정. **안전 중지 · 후속 호출 보류는 그대로.**
3. **해제** — 띠 [해제 · 하차 재개](또는 알림 패널 안전 탭) → 기존 `SAFETY_ACK`(하차 재개). [오탐지]도 해제. 세 곳 모두 정상으로.

하나의 경고 id(`SA-n`)가 세 화면을 모두 가리킨다. 카드 핀 id는 트럭 추적 ID(`#n`).

## 팀 확인이 필요한 것 (임의로 정하지 않고 지금 값만 표시)

- **이벤트 형식**: 요청서 3-5의 `safety_alert / safety_ack / safety_clear` 대신 기존 형식을 썼다 — `SAFETY_ALERT` / **`SAFETY_SEEN`(새로 추가 = 요청서의 safety_ack)** / `SAFETY_ACK`(= 요청서의 safety_clear). 이름을 요청서대로 바꿀지 확인 필요.
- **3-2 이벤트 기록 → state 매핑**(베이 진입 → enter, 정지 + 적재함 상승 → unload, 효과 확정 → done, 비콘 근접 → 변화 없음): 이벤트 기록이 아니라 서버 상태(위 표)에서 바로 만든다. 결과는 같은 방향이지만 확인 필요.
- **대기 초과 기준**: 지금은 설정 › 목표 대기(`settings.wait.target_min`, 15분)를 넘으면 `overdue`. **작업 지연 배수**는 설정 › 지연 배수(1.3) 그대로.
- **작업자 위치**: 호모그래피 변환이 없어 덤프 반경은 베이 번호 기준 고정 위치, 후진 경로는 베이 앞 통로의 가정 위치에 그린다.
- **배치도 위 경고 위치(%)**: 데모 값 대신 그림 좌표에서 계산하므로 따로 정할 필요 없음(그림이 바뀌면 자동).
- **자동 해제와 '확인 전까지 고정'**: 기존 시뮬레이션은 아무도 확인하지 않으면 6분(가정값) 뒤 안전 경고를 자동 해제한다. 요청서의 '확인 전까지 고정'과 다르다 — 자동 해제를 없앨지 확인 필요(이번엔 바꾸지 않음).
- 화면의 차량번호 · 시간 · 수치는 시뮬레이션 값 — 카드 헤더에 "시뮬레이션 값", 말풍선에 "(가상)" 표시.
